# Игры в постах Telegram-канала

Один бот публикует в канал посты с играми. Любая кнопка поста открывает чат с ботом, и там читатель играет в свою игру: одно сообщение, которое перерисовывается при каждом нажатии. Так игра одинаково работает на всех устройствах. Личный экран прямо в посте Telegram на iPhone показывает через раз: с первого нажатия его нет, со второго-третьего появляется.

Бот работает с одним каналом (`CHANNEL_ID`), и люди попадают к нему в личку. Поэтому лучше держать отдельного бота для канала клиента, с его названием и аватаркой (BotFather).

| Игра | Команда публикации | Код | Текст поста |
|---|---|---|---|
| «Мемори» — найти шесть пар эмодзи на поле 3 × 4 | `/memory` | `games/memory/` | `games/memory/post.txt` |
| «Взломайте телефон» — подобрать пароль из 6 цифр за 5 попыток | `/post_phone` | `games/phone/` | `games/phone/post.txt` |

Остальные команды: `/games` — список игр и команд, `/stats` — статистика по каждой игре. Все команды работают только в личке с ботом и только для `ADMIN_IDS`.

## Устройство

```
bot/            запуск (python -m bot), настройки, команды в личке, ответ на чужие кнопки
game/           запуск на хостинге агентства (python -m game), то же самое, что python -m bot
games/memory/   «Мемори»
games/phone/    «Взломайте телефон»
tests/
deploy/         unit-файл systemd
```

Игры не пересекаются:

- **Кнопки.** Роутер каждой игры принимает только свой формат `callback_data`. У «Мемори» это `p:<карточка>` в посте и `c:<карточка>:<пост>:<ревизия>`, `new:-:<пост>:<ревизия>` в личном экране. У телефона все кнопки начинаются с `phone:`: `phone:0`…`phone:9`, `phone:del`, `phone:ok` в посте и `phone:<действие>:<пост>:<ревизия>` на экране игры. Клетки строки ввода и попыток — `phone:-`: в посте они, как и остальные кнопки, открывают игру в боте, на экране игры ничего не делают. Кнопки, которые не подошли ни одной игре, получают ответ «Экран устарел».
- **Игра в чате с ботом.** Нажатие на кнопку поста бот принимает и отвечает ссылкой `https://t.me/<бот>?start=<START игры>` (`memory`, `phone`), а Telegram сразу открывает чат с ботом. `/start memory` или `/start phone` присылает игру сообщением в личку и убирает прошлое сообщение с игрой и саму команду, так что в чате остаётся одна живая игра. Это сессия с номером поста `0` (`CHAT_GAME`), кнопки те же, что у личного экрана, нажатия перерисовывают сообщение (`editMessageText`). Прогресс сохраняется, повторный `/start` продолжает ту же партию. Личные экраны, которые игроки открыли в посте раньше, продолжают работать.
- **База.** Одна SQLite (`game.db`), у каждой игры свои таблицы. У «Мемори» это `sessions` и `processed_updates`. У телефона — `phone_posts`, `phone_sessions`, `phone_attempts` (журнал всех проверок для `/stats`) и `phone_processed_updates`.

Новая игра подключается так: пакет в `games/` с тем же набором (`TITLE`, `COMMAND`, `START`, `router`, `create_service`, `post_html`, `on_published`, `open_in_bot_chat`, `stats`), строка в `GAMES` в `bot/admin.py` и роутер в `bot/__main__.py`.

## Настройки (.env)

Файл `.env` лежит в корне проекта (образец — `.env.example`):

```
BOT_TOKEN=токен от BotFather
CHANNEL_ID=id канала, куда публикуются игры, например -1003844288830
ADMIN_IDS=id администраторов через запятую, например 111111111,222222222
SESSION_TTL_DAYS=7        # необязательно: через сколько дней без активности игра удаляется
DB_PATH=                  # необязательно: путь к базе, по умолчанию game.db в корне проекта
```

Бота нужно добавить администратором канала с правом «Публикация сообщений». Один бот может работать только в одном месте: если он запущен где-то ещё, остановите его там.

## Тексты постов

Тексты лежат в `post.txt` в папке каждой игры. Абзацы разделяются пустой строкой, можно использовать `<b>жирный</b>` и `<i>курсив</i>`. Место для кнопок отмечено строкой `[ПОЛЕ]` в «Мемори» и `[игра]` в телефоне. Правки применяются без перезапуска, но только к новым публикациям.

## Локальный запуск и тесты

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest -q
.venv/bin/python -m bot
```

## Сервер (systemd)

Нужен Python 3.11 или новее.

```bash
cd /opt/tg_ad_games
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest -q
cp deploy/tg_ad_games.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now tg_ad_games
systemctl status tg_ad_games
```

В выводе `status` должно быть `active (running)`. Если папка не `/opt/tg_ad_games`, поправьте пути в `deploy/tg_ad_games.service`.

Обновление — залить файлы и выполнить `systemctl restart tg_ad_games`. Незаконченные игры продолжатся с того же места. Логи — `journalctl -u tg_ad_games -n 100`, в реальном времени — `journalctl -u tg_ad_games -f`.

### Переход со старой версии (`tg_ad_game_emoji`, только «Мемори»)

Формат кнопок и таблицы «Мемори» не менялись, поэтому уже опубликованные посты продолжат работать, если перенести базу:

```bash
systemctl disable --now tg_ad_game_emoji
cp /opt/tg_ad_game_emoji/game.db /opt/tg_ad_games/game.db
```

В `.env` переименуйте `ADMIN_ID` в `ADMIN_IDS` (старое имя тоже понимается). Команда публикации «Мемори» теперь `/memory` вместо `/publish`.
