# Игры в постах Telegram-канала

Бот публикует в канал посты с играми — сам, от своего имени: он админ канала. Читатель играет прямо в посте: первое нажатие заменяет пост у него личным экраном с его собственной игрой (эфемерное сообщение), остальные видят обычный пост.

Пересылать пост из бота в канал нельзя: в пересланном посте кнопки неактивны.

В «Мемори» и «Взломайте телефон», если личный экран не открылся (Telegram вернул ошибку), кнопка ведёт в чат с ботом, и игра идёт там. В `oplatit_button` перехода в личку нет: оба экрана работают внутри поста.

Бот работает с одним каналом (`CHANNEL_ID`). Его название и аватарка видны в подписи поста, если в канале включены подписи авторов, поэтому для канала клиента лучше держать отдельного бота (BotFather).

| Игра | Команда публикации | Код | Текст поста |
|---|---|---|---|
| «Мемори» — найти шесть пар эмодзи на поле 3 × 4 | `/memory` | `games/memory/` | `games/memory/post.txt` |
| «Взломайте телефон» — подобрать пароль из 4 цифр за 5 попыток | `/post_phone` | `games/phone/` | `games/phone/post.txt` |
| `oplatit_button` — раскрыть лонгрид о платежах | `/oplatit_button` | `games/oplatit_button/` | `intro.txt`, `post.html` в папке игры |

Остальные команды: `/games` — список игр и команд, `/stats` — статистика по каждой игре. Все команды работают только в личке с ботом и только для `ADMIN_IDS`. Остальным `/start` отвечает «Игра проходит в нашем канале @… — нажимайте кнопки в посте», а команды публикации просто не срабатывают.

**Защита от дурака.** Команда публикации сначала присылает админу в личку сам пост и вопрос «Вы уверены, что хотите опубликовать этот пост?». «Да» — пост уходит в канал (ровно тот, что показан), «Нет» — не уходит. Повторное «Да» второй пост не публикует. После перезапуска бота неотвеченный вопрос устаревает — команду нужно отправить ещё раз.

**Как узнать id нового админа:** он пишет боту `/start`, а в логах появляется `start user=<id> admin=False`. Этот id добавляется в `ADMIN_IDS`, бот перезапускается.

## Устройство

```
bot/            запуск (python -m bot), настройки, команды в личке, ответ на чужие кнопки
game/           запуск на хостинге агентства (python -m game), то же самое, что python -m bot
games/memory/   «Мемори»
games/phone/    «Взломайте телефон»
games/oplatit_button/  интерактивный лонгрид о платежах
tests/
deploy/         unit-файл systemd
```

Игры не пересекаются:

- **Кнопки.** Роутер каждой игры принимает только свой формат `callback_data`. У «Мемори» это `p:<карточка>` в посте и `c:<карточка>:<пост>:<ревизия>`, `new:-:<пост>:<ревизия>` в личном экране. У телефона все кнопки начинаются с `phone:`: `phone:0`…`phone:9`, `phone:del`, `phone:ok` в посте и `phone:<действие>:<пост>:<ревизия>` на экране игры. Клетки строки ввода и попыток на экране игры — `phone:-`, они ничего не делают; в посте клетки — `phone:open` и, как остальные кнопки, открывают личный экран. Кнопки, которые не подошли ни одной игре, получают ответ «Экран устарел».
- **Пост или экран игры** определяется по `callback_data`. Клетки строки ввода в посте телефона — `phone:open` (в старых постах — `phone:-`, их бот тоже узнаёт).
- **Личный экран в посте.** Нажатие на кнопку поста бот принимает и присылает на место поста эфемерное сообщение только для этого игрока (`replace_callback_query_message`). Нажатая цифра или карточка сразу засчитывается, «Удалить» и «Проверить» только открывают экран. Сессия привязана к посту: у каждого поста своя партия. Повторное нажатие в посте открывает ту же партию заново.
- **Игра в чате с ботом (запасной путь).** Если личный экран не открылся, бот отвечает на нажатие ссылкой `https://t.me/<бот>?start=<START игры>` (`memory`, `phone`), а Telegram сразу открывает чат с ботом. `/start memory` или `/start phone` присылает игру сообщением в личку и убирает прошлое сообщение с игрой и саму команду, так что в чате остаётся одна живая игра. Это сессия с номером поста `0` (`CHAT_GAME`), кнопки те же, что у личного экрана, нажатия перерисовывают сообщение (`editMessageText`). Прогресс сохраняется, повторный `/start` продолжает ту же партию. Личные экраны, которые игроки открыли в посте раньше, продолжают работать.
- **База.** Одна SQLite (`game.db`), у каждой игры свои таблицы. У «Мемори» это `sessions` и `processed_updates`. У телефона — `phone_posts`, `phone_sessions`, `phone_attempts` (журнал всех проверок для `/stats`) и `phone_processed_updates`.
- **`oplatit_button`.** Первый экран состоит только из подводки и кнопки «Оплатить». Нажатие показывает этому читателю лонгрид; шесть разделов свёрнуты по умолчанию и раскрываются нажатием на заголовки. Кнопка «Отменить платёж» в конце возвращает подводку и «Оплатить» на том же личном экране. Повторное открытие работает без новых сообщений. Публичный пост не редактируется. Кнопки используют отдельный префикс `oplatit_button:`. Предпросмотр в личке админа позволяет проверить весь цикл до публикации. Таблицы `oplatit_posts` и `oplatit_events` хранят снимки содержимого и успешные открытия/отмены. `/stats` считает только опубликованные посты и действия читателей в них; предпросмотры исключены. Сворачивание разделов выполняется приложением Telegram и в статистику не попадает.

Новая игра подключается так: пакет в `games/` с набором (`TITLE`, `COMMAND`, `router`, `create_service`, `post_html`, `on_published`, `stats`), строка в `GAMES` в `bot/admin.py`, сервис в `Dispatcher` и роутер в `bot/__main__.py`. `START` и `open_in_bot_chat` нужны только играм с переходом в личку. Для снимка материала до отправки предпросмотра предусмотрен `prepare_publication() → (html, publication)`: `on_preview` сохраняет этот снимок для предпросмотра, а `on_published` получает его параметром `publication` после подтверждения.

## Настройки (.env)

Файл `.env` лежит в корне проекта (образец — `.env.example`):

```
BOT_TOKEN=токен от BotFather
CHANNEL_ID=канал, куда публикуются игры: id (-1003844288830) или @username (@alfadigital_jobs)
ADMIN_IDS=id администраторов через запятую, например 111111111,222222222
SESSION_TTL_DAYS=7        # необязательно: через сколько дней без активности игра удаляется
DB_PATH=                  # необязательно: путь к базе, по умолчанию game.db в корне проекта
```

Бота нужно добавить администратором канала с правом «Публикация сообщений». Один бот может работать только в одном месте: если он запущен где-то ещё, остановите его там.

## Тексты постов

Тексты лежат в `post.txt` в папке каждой игры. Абзацы разделяются пустой строкой, можно использовать `<b>жирный</b>` и `<i>курсив</i>`. Место для кнопок отмечено строкой `[ПОЛЕ]` в «Мемори» и `[игра]` в телефоне. Правки применяются без перезапуска, но только к новым публикациям.

Пароль телефона (`1711`, ДДММ: 6 кнопок в ряд на iPhone не помещаются) задан в `games/phone/logic.py`, константа `PASSWORD`.

У `oplatit_button` подводка хранится в `games/oplatit_button/intro.txt`, лонгрид с готовой HTML-разметкой — в `games/oplatit_button/post.html`. Кнопки добавляются кодом. Текст фиксируется при создании предпросмотра: правки файлов после этого не меняют ни показанный материал, ни публикацию после «Да», ни старые посты. Снимки сохраняются в базе и продолжают работать после перезапуска. Если записи о посте ещё нет, первое нажатие создаёт её из файлов игры — по тому же принципу, что сессии других игр; предварительная регистрация поста для открытия не требуется. В личном предпросмотре обе кнопки редактируют обычное сообщение (`editMessageText`); в канале открывают и редактируют эфемерный экран. Публиковать нужно командой бота от его лица, как и другие игры.

Исходная анимированная обложка находится в `games/oplatit_button/cover_oplatit_button.gif`. Для отправки подготовлена копия `cover_oplatit_button_telegram.mp4` (H.264 без звука); именно она загружается как анимация внутри rich message. Сырой GIF возвращал от Telegram `RICH_MESSAGE_VIDEO_INVALID`. Вместе с MP4 передаются размеры, длительность и миниатюра `cover_oplatit_button_thumbnail.jpg`. При замене исходника нужно подготовить новую копию, миниатюру и обновить параметры в `render.py`; FFmpeg на сервере не нужен. Обычная загрузка папки `games` переносит все готовые файлы.

Обложка появляется над лонгридом после нажатия «Оплатить» и убирается вместе с ним при отмене; первый экран состоит только из подводки и синей кнопки. Обе кнопки — «Оплатить» и «Отменить платёж» — используют синий стиль `primary`.

## Локальный запуск и тесты

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest -q
.venv/bin/python -m bot
```

## Сервер (systemd)

Нужен Python 3.11 или новее.

```bash
cd /opt/tg_ad_games
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest -q
cp deploy/tg_ad_games.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now tg_ad_games
systemctl status tg_ad_games
```

В выводе `status` должно быть `active (running)`. Если папка не `/opt/tg_ad_games`, поправьте пути в `deploy/tg_ad_games.service`.

### Обновление тестового бота с Mac

Код и тексты редактируются в локальном проекте. Для загрузки актуальных файлов выполните в терминале Mac:

```bash
cd /Users/elizavetagusenkova/tg_ad_games && rsync -av --exclude='__pycache__/' bot games tests deploy README.md requirements.txt root@72.56.22.151:/opt/tg_ad_games/
```

Команда передаёт только перечисленные папки и файлы. Настройки `.env`, виртуальное окружение, база и её копии остаются на сервере; удаления файлов нет.

Затем в терминале сервера:

```bash
cd /opt/tg_ad_games && .venv/bin/python -m pytest -q && systemctl restart tg_ad_games && systemctl status tg_ad_games --no-pager
```

После правок текста `oplatit_button` создайте новый предпросмотр командой `/oplatit_button`: он сохранит актуальную версию файлов. Незаконченные игры продолжатся с того же места. Логи — `journalctl -u tg_ad_games -n 100`, в реальном времени — `journalctl -u tg_ad_games -f`.

Локальный Git-репозиторий уже связан с `git@github.com:lissguss/tg_ad_games.git` (`origin`). `.env`, базы и резервные копии исключены через `.gitignore`. Обмен через GitHub настраивается отдельно: фиксация изменений локально, отправка в GitHub и обновление выбранной ветки на сервере. До перехода на этот процесс используется загрузка с Mac, описанная выше.

### Два бота: тестовый и продакшн

На одном сервере работают два независимых бота, у каждого своя папка, `.env`, база и сервис:

| | Папка | Сервис | Канал |
|---|---|---|---|
| тестовый | `/opt/tg_ad_games` | `tg_ad_games` | тестовый канал |
| продакшн | `/opt/tg_ad_games_prod` | `tg_ad_games_prod` | канал клиента |

Новый код сначала заливается в тестовую папку и проверяется там, потом переносится в продакшн:

```bash
rsync -a --exclude .git --exclude .venv --exclude .env --exclude 'game.db*' --exclude __pycache__ --exclude .pytest_cache /opt/tg_ad_games/ /opt/tg_ad_games_prod/
cd /opt/tg_ad_games_prod && .venv/bin/pip install -q -r requirements.txt && .venv/bin/python -m pytest -q && systemctl restart tg_ad_games_prod
```

Первичная настройка продакшна — та же, что выше, с папкой `/opt/tg_ad_games_prod` и файлом `deploy/tg_ad_games_prod.service`. Логи — `journalctl -u tg_ad_games_prod -f`.

### Переход со старой версии (`tg_ad_game_emoji`, только «Мемори»)

Формат кнопок и таблицы «Мемори» не менялись, поэтому уже опубликованные посты продолжат работать, если перенести базу:

```bash
systemctl disable --now tg_ad_game_emoji
cp /opt/tg_ad_game_emoji/game.db /opt/tg_ad_games/game.db
```

В `.env` переименуйте `ADMIN_ID` в `ADMIN_IDS` (старое имя тоже понимается). Команда публикации «Мемори» теперь `/memory` вместо `/publish`.
